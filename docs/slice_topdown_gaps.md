# Top-down validation slice: gaps

`samples/topdown_slice` is a small arena, not a complete game. WASD moves the blue player and Space shoots; red enemies arrive in waves, follow around the wall, and contact damages the player with a particle burst. Killed enemies drop pooled coins (`CoinPickup`) that the player collects for score. The HUD shows health, the wave number with its time left, and the coin count. P or Escape pauses (a centered `status_text` shows PAUSED; the live arena nodes are deactivated and exactly those are reactivated, parked pool instances stay parked). On player death a GAME OVER screen shows wave and coins; R, or `restart_delay` seconds (default 3), restarts the scene and `ArenaRules::on_start` resets the HUD. Registered `ArenaRules` properties in `scenes/main.scene.json` tune player, enemy and bullet speed; `gravity_scale` is zero on both actors. The arena uses a solid Tilemap perimeter. Assets are intentionally reused placeholder art.

- The shared command registry exists (`arcane_tooling`) with `prop.list/get/set`, so registered `ArenaRules` properties can be listed and set (persist, dry run, rejection of unknown properties/bad types) through it; `tests/test_topdown_commands.cpp` covers this on a copy of the slice. Still missing: the `arcane` executable, so none of this is reachable from a shell; and node/component create or delete, project creation, validate and format commands. Creating the slice's nodes still means editing v2 JSON or the editor. Opening the project loads its module and validates the scene.
- AF10B is implemented: `arcane run`, `arcane test`, `arcane export` and `arcane_player --headless` run display-free fixed frames. The windowed player and the editor still need a display (Xvfb is sufficient). `scripts/export-game.sh` uses `arcane export`. `render` is not a command yet.
- Movement, pursuit and combat now come from reusable components: `TopDownController2D` (WASD), `SteeringAgent2D` with grid A* over the wall Tilemap (the enemy walks around the interior wall), `Health`/`Hurtbox`/`Hitbox`/`Projectile` (contact damage, Space fires pooled bullets from a `Spawner2D`), and `ArenaRules` is only glue (HUD, hit burst, pause, game over and restart). Waves (`EnemySpawner`, spawn points picked by a seeded LCG away from the player, `wave_duration`/`intermission`/`base_enemies`/`enemies_per_wave` on `ArenaRules`) and coin pickups (`CoinSpawner`, `pickup` layer) now exist. Still missing: line of sight and ranged enemy AI, knockback and melee, separation between enemies, and a dedicated enemy attack collider (`enemy_attack` layer is declared but unused because a node has one collider).
- Physics now has collision layers, contact/trigger callbacks and spatial queries, but still no impulse API for knockback. Navigation is a uniform grid built from solid tiles, not a mesh, and ignores moving obstacles.
- No native Windows/MSVC or manual visual validation was performed. The automated GL/export checks use Xvfb and Mesa; they do not prove appearance or device input on Windows.
