# Foundation A — technical decisions

Settled 2026-10-25, for `foundation-a-setup`. Contracts are the ones listed
in vision doc section 16, plus a few forced by implementation. Entries
marked **delegated** had no explicit instruction tonight and adopt the
doc's stated default leaning; the justification is why that leaning was
taken as-is rather than something else.

| # | Contract | Decision | Status |
| - | -------- | -------- | ------ |
| 1 | Repo layout | V2 lives at the **repo root** (`CMakeLists.txt`, `engine/`, `player/`, `samples/`, `tests/`, `scripts/`, `third_party/`, `docs/`). Copied V1 files (root `src/`, `include/`, `dependencies/`, `examples/`, `assets/`, `stb/`, `github/`, `*.sln`/`*.vcxproj*`, `config.ini`, `scene.txt`, `imgui.ini`) were removed in one commit. V1 stays intact in git history (first two commits on this branch) and at `franklinjr12/Arcane2DEngine`. | Settled (explicit instruction, Franklin 22:46 BRT) |
| 2 | Fixed timestep | 60 Hz (`1/60 s`) accumulator, up to 5 catch-up steps per frame, remainder discarded past the cap to avoid a spiral of death; render happens once per frame regardless of step count (`arcane::FixedTimestep`, `engine/include/arcane/time.hpp`). Pure logic, no GL/platform dependency, unit-tested in `tests/test_timestep.cpp`. | **Delegated** — doc's stated default (section 16) |
| 3 | Pixel and physics units | Foundation A does not yet wire Box2D bodies to renderable sprites, so no pixels-per-meter conversion exists in engine code yet. Decision recorded now so later foundations don't improvise: **32 px = 1 m**, origin top-left in screen/window pixel space (y-down, matching GLFW/OpenGL framebuffer coordinates as used by the renderer today), Box2D world space is y-up as Box2D expects; the conversion lives at the boundary (future `PhysicsWorld`/`Transform` sync code), not inside the renderer or inside Box2D. | **Delegated** — not yet exercised; recorded ahead of need |
| 4 | Native module registration ABI | Plain-C exported entry point `arcane_get_game_api(uint32_t engine_api_version) -> const GameApi*`, versioned via `arcane::kGameApiVersion` (`engine/include/arcane/game_api.hpp`). Returns `nullptr` on version mismatch; the engine's `GameModule::load` (`engine/src/module.cpp`) treats that as a load failure rather than crashing. The struct is a flat C POD (function pointers + a C string); no C++ ABI (vtables, exceptions, STL types) crosses the boundary. Cross-platform dlopen/LoadLibrary wrapper lives in `arcane::GameModule`. | Settled |
| 5 | Property metadata implementation | Not needed for Foundation A (no component/property registry yet — `sample_game` only implements the four lifecycle callbacks). | Open (not needed for Foundation A) — default leaning: simple explicit registry, minimal templates/macros |
| 6 | Scene graph storage and component lookup | Not needed for Foundation A (no scene graph yet). | Open (not needed for Foundation A) — default leaning: simple owned nodes/components with stable IDs |
| 7 | Scene/project JSON schema | Not needed for Foundation A beyond proving nlohmann-json links and round-trips (`tests/test_json.cpp`). | Open (not needed for Foundation A) — default leaning: versioned files, typed properties, stable asset/entity IDs |
| 8 | Game/editor module reload strategy | Not needed for Foundation A (no editor yet; `arcane_player` loads a module once at startup). | Open (not needed for Foundation A) — default leaning: rebuild + reload/restart Play, no live hot-swap |
| 9 | Editor mode isolation | Not needed for Foundation A (no editor yet). | Open (not needed for Foundation A) |
| 10 | Font/text implementation | Not needed for Foundation A (no in-game UI text yet; ImGui's built-in font is only exercised by `test_imgui_context`). | Open (not needed for Foundation A) — default leaning: start simple |
| 11 | Shared library and compiler support | Linux: GCC 14+ / Clang 19+, CMake 3.28+, Ninja/Make. Windows: MSVC v143 (VS 2022 17.10+) or MinGW-w64 GCC 14 (posix threads), CMake 3.28+. `CMakeLists.txt` sets `cmake_minimum_required(3.22)` for broader compatibility but the toolchains actually validated tonight are the ones above. Windows path is CMake-correct and mingw-cross-compiled from Linux, but **untested on native Windows/MSVC** — call this out everywhere (README, PR body). | Settled |
| 12 | Dependency acquisition/versioning | Vendoring, not a package manager: pinned upstream sources (sha256-checksummed, see `third_party/MANIFEST.txt`) are fetched/trimmed by `scripts/fetch-deps.sh` into `third_party/<name>/`, and the **trimmed result is committed** to the repo so a fresh clone builds fully offline without ever running that script. `fetch-deps.sh` exists only to reproduce/refresh the vendored copies from pristine upstream archives (supports `ARCANE_DEPS_CACHE=/dir` to prefer a local cache over the network). No vcpkg/Conan/CPM/FetchContent-at-configure-time, no `apt` in any script. | Settled |
| 13 | Box2D version | v3.2.0 (not v3.1.1): newer stable tag available in the pinned dependency cache tonight; v3's C API is used headlessly only (`tests/test_physics_headless.cpp`), no breaking surface exposed to the rest of the engine yet. | **Delegated** |
| 14 | Initial editor feature boundary | Not applicable — Foundation A has no editor; it is player/runtime only. | Open (not needed for Foundation A) — default leaning for later: scene tree, Inspector, viewport, save/load, Play/Stop |
| 15 | Release package organization | Not needed for Foundation A (`arcane_player` runs out of the build tree: `bin/` holds the executable, `arcane_runtime` shared lib, and `sample_game` module side by side, `$ORIGIN` rpath on Linux). | Open (not needed for Foundation A) — default leaning: runtime + player + game module + assets, automate later |
| 16 | Public API / ABI hygiene | Public headers under `engine/include/arcane/` avoid leaking third-party headers (GLFW/GL) where cheap: `Window` hides its GLFW state behind a pimpl (`Window::Impl`); `arcane/export.hpp` provides `ARCANE_API` (dllexport/dllimport on Windows, `visibility("default")` on Linux) and `ARCANE_GAME_API` for the module entry point; the whole build sets `CMAKE_CXX_VISIBILITY_PRESET hidden` so only explicitly marked symbols are exported. | Settled |
| 17 | Logging | Small `std::format`-based logger (`arcane::log`/`log_message`), levels Trace..Error, category tag, always-on stderr sink plus an optional file sink (`log_set_file`). No external logging library. | Settled |
| 18 | Vendored third-party build integration | GLFW and Box2D are pulled in via their own `CMakeLists.txt` as `EXCLUDE_FROM_ALL` subdirectories (examples/tests/docs disabled via cache vars); glad, Dear ImGui, and miniaudio are built as small hand-written `add_library(... STATIC ...)` targets directly against the vendored sources (they don't ship/need their own CMake here). ImGui is compiled with its GLFW+OpenGL3 backends now (for the later editor) but is only exercised headlessly (`test_imgui_context`) in Foundation A — no GL-backed ImGui test yet. | Settled |
| 19 | Sanitizer leak suppressions | Under `ARCANE_SANITIZE`, GL-labeled tests set `ASAN_OPTIONS=detect_leaks=0` (LSan only; ASan error detection stays on) because the Mesa llvmpipe software rasterizer JIT-compiles shader code at runtime into pages LSan can't attribute to a loaded module (`<unknown module>` stack frames) and reports as leaked at process exit. This is driver behavior, not an application leak, and is isolated to the two GL-labeled tests (`tests/CMakeLists.txt`); all non-GL tests still run with full leak detection. | Settled |
| 20 | GL test skip behavior | GL-labeled tests use `SKIP_RETURN_CODE 77` so that a display-less CI box reports SKIP rather than FAIL; under `xvfb-run -a` (used throughout tonight) they run and pass for real rather than skipping. | Settled |

## Toolchains actually exercised tonight

- gcc 14 Debug — required, must pass.
- clang 19 + `ARCANE_SANITIZE=ON` (ASan+UBSan) — passes.
- `x86_64-w64-mingw32-g++` cross-compile (`cmake/toolchains/mingw-w64-x86_64.cmake`), build-only, tests not run.
- All three driven by `scripts/build-and-test.sh`, which also runs `ctest` under `xvfb-run -a` for the two configs that run tests.
