# Platformer validation slice — engine gap list

Slice: `samples/platformer_slice` (project, two levels) + `samples/platformer_slice_game` (module: `SliceRules`,
`SliceTrigger`, `PatrolEnemy`).
Exercises: tilemap levels (2 maps each, solid tiles, pits), `PlatformerController2D`, hero `Animator` graph
(idle/run/jump/fall/hurt), HUD (score text, health bar, banner text, restart button), null-backend audio cues,
particle burst, export via `scripts/export-game.sh`. Art/sounds/scenes are generated by
`samples/platformer_slice/make_assets.py`.

GS2 (v2 of the slice) now also exercises:

- **Trigger events:** coins, spikes, checkpoints and the goal are static sensor bodies carrying a `SliceTrigger`
  component (`kind` property); `on_trigger_enter` reports the Player to `SliceRules`, which no longer tests any boxes.
- **Checkpoints and respawn:** touching a checkpoint further along than the current one stores a respawn point; a pit
  fall with health left teleports (`RigidBody2D::teleport`) there, otherwise it is game over.
- **Camera follow + parallax in both levels:** `Camera2D` look-ahead and `bounds_tilemap`, plus a `ParallaxLayer` sky.
- **Animgraph states:** `hero.animgraph.json` drives idle/run/jump/fall/hurt through the `Animator`.
- **Enemy:** `PatrolEnemy` walks between two x limits; landing on it stomps it, any other contact hurts.
- **Pause:** the `pause` action (P / Escape) freezes gameplay by deactivating nodes; it resumes exactly those.
- **Scene switch:** the goal calls `SceneManager::request_switch` to `scenes/level2.scene.json`; the score carries over;
  Restart reloads the current level.

Tests: headless `test_platformer_slice`; GL tests `test_player_slice_frames`, `test_export_platformer_slice`; replay
regression `test_platformer_replay` (`samples/platformer_slice/tests/level2_run.replay.json` crosses both level 1
checkpoints, reaches level 2 and respawns there; strict trace compare on GCC Debug only; needs GL because the
`--headless` runner has no SceneManager, see gap 13). `test_replay_player` still replays `replays/walk_jump.replay.json`.

Gaps found while building it (most important first). Each has the workaround used in the slice.

1. **(FIXED in GP1: `RigidBody2D::teleport`; pit falls respawn.)** No teleport / node→body position sync.** `PhysicsWorld` only writes body→node after `rebuild`. Respawn and
   checkpoints are impossible; "Restart" resets score/health only.
2. **(FIXED in GP1: `Component::scene()`, coins use `destroy_node`.)** Components cannot reach their `Scene`.** No `destroy_node`/spawn from gameplay code. Workaround: collected coins
   are parked at (-100000, -100000). Needs a scene accessor on `Component`/`Node` (or a `GameContext` in `on_update`).
3. **(FIXED in GP2, exercised by GS2: `on_trigger_enter/exit`, `on_collision_enter/exit`, layers/masks, raycast/overlap queries; the slice uses sensor triggers (`SliceTrigger`) for coins, spikes, checkpoints and the goal.)** No collision/trigger events.** `Collider2D::is_sensor` exists but nothing reports overlaps. Workaround: manual AABB
   tests against hard-coded sizes duplicated from the scene.
4. **(FIXED in GP4: every HUD element has a stable `id` (already in the v2 format), `Hud::find_text/find_bar/find_image/find_button`; the slice looks up `score`, `health`, `banner`.)** HUD text/bar elements had no ids.**
5. **(FIXED in GP1: `arcane/assets.hpp`, `GameContext::play_sound`, `AudioSource::play`; the `idle_clip`/`run_clip` properties remain as authored data.)** No runtime asset-id → path resolution.** Audio cues use a literal `"assets/coin.wav"` string; `AudioSource` has no
   "play now" call and `asset_id_for_relative_path` lives in the editor library, so the module also receives clip ids as
   scene properties (`idle_clip`, `run_clip`). On a real audio device the relative path would depend on the cwd.
6. **(FIXED in GP1: `GameContext::request_restart`; Restart button reloads the level.)** No scene reload / restart API**, so full level reset (coins, player) is not possible (see 1, 2).
7. **(FIXED in GP4: `Sprite::flip_x/flip_y`, `Collider2D::mirror_with_sprite`; the slice flips the Sprite.)** Sprite flip was only negative `scale.x`** on the node. Not verified visually (no screenshot tooling run tonight),
   and the collider is not mirrored.
8. **(FIXED in GP3: `Camera2D` look-ahead, `bounds_tilemap`, `GameContext::viewport_size()`, `ParallaxLayer`; the slice uses them.)** No camera follow component / bounds / viewport size for modules.** Follow is hand-written; the left clamp (400)
   assumes the 800-wide design view.
9. **(FIXED in GP2: tileset `tags`, `GameContext::tile_at/tagged_tile_at`.)** No tile queries for gameplay** (hazard/pickup tiles): spikes and coins are separate nodes. One-way platforms: done in FE17 (`Collider2D::one_way`).
10. **(FIXED in GP4: `arcane.animgraph` v2, `Animator` component, `animgraph.*` commands, frame events via `Component::on_animation_event`, editor Animation Graph panel; the slice drives `hero.animgraph.json`.)** No animation state machine / events**.
11. **Player has no module render hook with scene/renderer access**, and `arcane_player` builds `TilesetCache` from
    `list_animation_clip_assets` (works only because both are `.json`): a dedicated tileset catalog is missing.
12. **(PARTLY FIXED in GS2: pause and scene switching are covered, headlessly in `test_platformer_slice` and in a replay
    through the windowed player.)** Still not covered: gamepad play-through, save data, a menu, window resize
    behaviour, visual checks (the slice has one render golden, `tests/golden/render/platformer_slice_f30.png`, and nobody
    has looked at the other frames), native Windows/MSVC.
13. **`arcane_player --headless`, `arcane run` and `arcane test` own no `SceneManager`**, so a level switch cannot happen
    there: the goal does nothing in those runs (the replay regression has to use the windowed player, hence GL).
    Gameplay that needs `active_scene_manager()` has no display-free test path.
14. **Pause is a node-by-node `set_active(false)` sweep** done by the module (everything but the Level node, camera and
    HUD). There is no engine-level time scale or paused-scene flag, so anything spawned while paused is not frozen.
15. **Carry-over between levels is a module-level static** (`g_carried_score`), because `SceneManager` only carries
    roots flagged `persistent`, not plain values. It is not saved and would leak between two `GameContext`s in one
    process.
